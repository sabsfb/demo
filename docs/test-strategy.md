# 测试策略（脱敏概述）

> 本文档概述被测系统的测试工程方法论。所有内容均为脱敏后的通用描述，不含真实业务数据、内网地址与安全细节。

## 1. 测试分层

用 pytest 的 `marker` 把测试分成四层，互不耦合、独立运行、按需触发：

| 层级 | marker | 范围 | 触发时机 |
|---|---|---|---|
| 单元测试 | `unit` | 函数 / 类级逻辑（解析、表格合并、配置加载） | PR 必跑，最快 |
| 接口测试 | `api` | REST API 端到端（正常 / 异常 / 边界） | PR 必跑 |
| 集成测试 | `integration` | 跨模块协作、CLI 批处理全流程 | 需 LibreOffice / ImageMagick 环境 |
| 回归测试 | `regression` | 缺陷修复回归 + 全量回归 | 守护历史缺陷不复发 |

运行示例：

```bash
pytest -m unit                 # 只跑单元
pytest -m api                  # 只跑接口
pytest -m "bug('BUG-XXX')"     # 跑单个缺陷的回归
pytest -m regression           # 全量回归
```

## 2. 已知问题管理

对尚未修复的已知问题，用 `xfail` 标记管理，既不污染通过率、又能持续跟踪：

- 已知问题在报告中以"阻塞缺陷"口径汇总；
- 每个阻塞缺陷对应一条**回归用例**，修复后该用例应转 `xpass` 并移除 `xfail`；
- 本项目累计 5 个阻塞缺陷，对应 6 条回归用例。

## 3. 覆盖率测量

- 用 `pytest-cov` / `coverage` 采集行覆盖率；
- 在"同步盘"（如 OneDrive）环境下跑覆盖率时，临时文件会被同步客户端加锁，需把覆盖率数据文件指向同步盘外的临时目录（如系统 Temp），避免擦除阶段 `INTERNALERROR`；
- 并行覆盖合并时，单文件临时数据也须落在同步盘外。

## 4. 变异测试策略

使用 `mutmut` 做变异测试，衡量测试套件对代码缺陷的"捕捉力"（kill rate）：

- 适配 pytest marker 选择策略，让变异测试只跑相关子集，避免误判；
- 修复了"绝对导入触发 trampoline 断言崩溃"的问题（改用相对导入规避）；
- 变异测试**不挂 push / PR 自动跑**，改为 `workflow_dispatch` 手动勾选（见 `trigger-guide.md`）；
- kill rate 从 12% 提升至 23.53%，提升来自补齐高覆盖测试与导入方式修复。

## 5. 度量体系

量化成果以汇总级数字呈现（详见本站"度量看板"）：

- 功能测试通过率、接口测试通过率；
- 变异测试 kill rate（killed / total）；
- 阻塞缺陷数 → 对应回归用例数；
- 累计定位缺陷数（功能 + 安全）。

## 6. 环境约定

- CI 使用预构建 Docker 镜像，集成测试 job 通过包管理器安装 LibreOffice / ImageMagick；
- 变异测试 job 对齐同一镜像方案，保证本地与 CI 行为一致。
