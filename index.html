知识库文件预处理系统 · 测试工程展示

一个面向电力行业知识库文档预处理系统的完整测试体系展示。本页为脱敏版，仅呈现测试架构、工程方法与量化成果，不含任何真实业务数据与安全细节。

Python + FastAPI 配置驱动 pytest 分层 GitHub Actions mutmut 变异测试

项目概述（脱敏）

被测系统做什么、怎么测的。

被测系统

某电力企业知识库文件预处理系统，Python + FastAPI，基于 YAML 配置驱动，提供批处理命令行（CLI）与 REST API 两种使用方式。

处理对象

6 类电力业务文档，涵盖运行、检修、调度等场景下的结构化文档，实现统一抽取与标准化预处理。

测试职责

功能 / 性能 / 安全三类测试全覆盖，累计定位 16 个缺陷（功能 12 + 安全 4），并建立分层自动化回归体系。

测试产出

pytest 自动化套件、CI 流水线、变异测试度量、缺陷回归用例库，以及综合测试报告。

测试体系

用 pytest marker 把测试分成四层，互不耦合、独立运行、按需触发。

unit

单元测试

函数 / 类级，最快，PR 必跑。覆盖文档解析、表格合并、配置加载等核心逻辑。

api

接口测试

面向 REST API 的端到端校验，覆盖正常 / 异常 / 边界输入。

integration

集成测试

跨模块协作场景，含 CLI 批处理全流程，依赖 LibreOffice / ImageMagick 环境。

regression

回归测试

缺陷修复回归 + 全量回归，标记已知问题（xfail），守护历史缺陷不复发。

运行方式举例：pytest -m unit 跑单元，pytest -m "bug('BUG-XXX')" 跑单缺陷回归。

CI/CD 架构

GitHub Actions 流水线：常规 job 自动跑，变异测试按需手动勾选。

关键设计：变异测试（mutmut）计算量大、耗时长，不随每次 push 自动跑。通过 workflow_dispatch + 输入项 run_mutation 实现按需手动勾选——平时省 CI 时长，需要时手动触发全量变异。详见 变异测试触发指引。

变异测试按需触发

把"贵但重要"的变异测试，做成可手动勾选的能力。

为什么按需

全量变异测试耗时可达成百上千分钟，占满 CI 资源。日常 PR 不需要它，只有发布前或专项评估才跑。

怎么触发

在仓库 Actions 页选择工作流 → Run workflow → 勾选 run_mutation → 确认即可。

配置要点

on: workflow_dispatch 增加布尔输入项；变异测试 job 加 if: inputs.run_mutation == true。模板见本仓库 .github/workflows/ci.yml。
